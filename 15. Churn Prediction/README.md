# Telecom Customer Churn Prediction

## О проекте
**Заказчик:** Оператор связи «ТелеДом».
**Бизнес-цель:** Создать модель машинного обучения для прогнозирования оттока клиентов (разрыва договора), чтобы заранее выявлять абонентов, планирующих отказаться от услуг. Это позволит предлагать им промокоды и специальные условия точечно, не тратя бюджет на удержание всех клиентов подряд.

## Логика решения
Задача сводится к бинарной классификации: для каждого абонента нужно предсказать, разорвёт ли он договор (1) или останется клиентом (0). Модель учится находить паттерны поведения, характерные для уходящих клиентов (тип контракта, способ оплаты, набор услуг, длительность обслуживания). Бизнес-ценность решения — инструмент раннего предупреждения для фокусировки маркетинговых затрат.

## Данные
Данные загружены из базы данных SQLite и объединены из четырех таблиц:
*   **contract:** информация о договорах (даты, тип оплаты, расходы).
*   **personal:** персональные данные (пол, пенсионер, наличие партнера/детей).
*   **internet:** данные об интернет-услугах (тип подключения, безопасность, ТВ).
*   **phone:** данные о телефонии.

**Целевая переменная:** Признак оттока, выделенный на основе даты окончания договора (`end_date`). 
*   0 — клиент остался (договор действует).
*   1 — клиент ушёл (договор расторгнут).
Итоговый датасет: 7043 клиента, 21 признак, дисбаланс классов 1:5.4 (15.6% оттока).

## Задачи и методы
1.  **ETL и препроцессинг:** Загрузка данных из SQLite (`SQLAlchemy`), обработка пропусков, кодирование категориальных признаков (`OneHotEncoder`, `OrdinalEncoder`), масштабирование (`StandardScaler`).
2.  **Feature Engineering:** Созданы новые признаки (длительность в днях, средний чек, динамика тарифа, число услуг).
3.  **Пайплайн:** Для автоматизации предобработки использованы `Pipeline` и `ColumnTransformer` из `Scikit-learn`.
4.  **Эксперименты с признаками:** Сформированы два датасета — `df_full` (18 признаков, все услуги отдельно) и `df_agg` (11 признаков, только общее число услуг).
5.  **Работа с дисбалансом:** Для борьбы с дисбалансом классов (1:5.4) использованы веса классов (`class_weights`), чтобы модель не игнорировала редкий класс «ушедших».
6.  **Масштабное моделирование:** Обучено **8 моделей** (2 датасета × 4 класса: Dummy, RandomForest, CatBoost, Keras MLP). Для подбора гиперпараметров использован `GridSearchCV` (20 комбинаций × 5 фолдов = **100 обучений на каждый датасет**).
7.  **Оценка:** Выбор лучшей модели по метрике **ROC-AUC** на кросс-валидации (`StratifiedKFold`), финальное тестирование на отложенной выборке, анализ матрицы ошибок и важности признаков.

## Стек
*   **Язык и работа с данными:** Python, Pandas, NumPy, SQLAlchemy, SQL (SQLite).
*   **Препроцессинг:** Scikit-learn (`Pipeline`, `ColumnTransformer`, `OneHotEncoder`, `OrdinalEncoder`, `StandardScaler`).
*   **ML и нейросети:** Scikit-learn (`RandomForestClassifier`, `MLPClassifier`, `GridSearchCV`, `StratifiedKFold`), CatBoost, TensorFlow/Keras.
*   **Визуализация:** Matplotlib, Seaborn.

## Результаты и интерпретация

**Качество финальной модели (CatBoost на df_agg):**
*   **ROC-AUC (test):** 0.9300 (превышает целевой порог 0.85).
*   **Accuracy:** 0.9114, **Recall:** 0.7564, **F1-мера:** 0.7273.
*   *Проверка адекватности:* Dummy-модель (базовая константа) показала ROC-AUC 0.5000 и Recall 0.0000, что подтверждает: модель реально различает классы, а не угадывает.

**Ключевые инсайты для бизнеса:**
*   **Критическое окно оттока:** 1–4 года. Пик приходится на 30–42 месяца (до 32.3% оттока). После 60 месяцев лояльности отток практически исчезает.
*   **Самый опасный сегмент:** «Дорогие» клиенты (топ-25% по чеку) со стажем 1–4 года на долгосрочных контрактах, которым не предлагают обновления тарифа. Их отток составляет 29.5%, хотя они приносят почти половину выручки (49.1%).
*   **«Слепые зоны»:** Модель хуже ловит клиентов на помесячной оплате (`Month-to-month`) и со сроком обслуживания 5+ лет.

**Архитектурное решение:**
Сравнив два датасета, я выбрала агрегированный `df_agg` (11 признаков) вместо `df_full` (18 признаков). Он не уступает по качеству (ROC-AUC в пределах погрешности), но дает **лучший Recall (+2.8 п.п.)**, проще интерпретируется и снижает риск переобучения. Главный предиктор — длительность обслуживания (`tenure_days`, 55.48% важности).

**Бизнес-ценность:**
Модель выступает как инструмент раннего предупреждения, который ловит до 76–83% уходящих клиентов. Это позволяет точечно фокусировать бюджет на удержание (Q4 и клиенты в «критическом окне»), а не тратить его на всю базу. *(Примечание: точный экономический эффект требует данных о LTV и стоимости удержания).*
