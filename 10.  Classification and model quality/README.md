# RiskDrive: Оценка вероятности быть виновником ДТП

## О проекте
**Заказчик:** Каршеринговая компания.

**Бизнес-цель:** Создать систему оценки риска ДТП по выбранному маршруту движения, которая предупреждает водителя при высоком уровне вероятности ДТП с любым повреждением транспортного средства.

## Логика решения
*   Задача сводится к бинарной классификации: для каждого участника ДТП (управляющего автомобилем) нужно предсказать, является ли он виновником (1) или просто участником (0).
*   В реальной системе мы не предсказываем сам факт ДТП, а отвечаем на вопрос: *«Похож ли текущий водитель и условия поездки на типичного виновника аварий из прошлых ДТП?»*.
*   Факторы, отличающие виновника от невиновного, являются индикаторами рискованного поведения (прокси для оценки риска).

## Данные
Данные загружены из базы данных PostgreSQL и объединены из трех таблиц:
*   **collisions:** общая информация о ДТП (погода, освещение, тип дороги, серьезность повреждений).
*   **parties:** информация об участниках (трезвость, использование телефона, страховка, целевая переменная `AT_FAULT`).
*   **vehicles:** информация об автомобилях (тип кузова, КПП, возраст авто).

**Очистка данных (SQL и Pandas):** 
*   Оставлены только участники типа «автомобиль» (`party_type = car`).
*   Исключены незначительные повреждения (царапины).
*   Удалены выбросы (например, возраст авто 161 год).
*   Обработаны пропуски. Итоговый датасет: **16 578 строк, 11 признаков**. Дисбаланс классов устранен (54% виновников / 46% невиновных).

## Исследовательский анализ (EDA): Ключевые инсайты
1.  **Сезонность:** Пик аварийности приходится на весну (март, апрель, май) — 26.4% всех аварий. Летом — спад. Для Калифорнии характерна двухпиковая сезонность (зимний дождь + весенняя активность).
2.  **Погода:** Самый опасный фактор — **туман** (доля фатальных ДТП в 2.8 раза выше, чем в ясную погоду). Дождь парадоксально безопасен (водители едут осторожнее).
3.  **Возраст автомобиля:** Самая опасная группа — **8–12 лет** (максимальная доля фатальных ДТП — 1.63%). Новые авто (0–3 года) — самые безопасные (0.95%). Водители старых авто (13+ лет) ездят осторожнее, поэтому у них низкая доля тяжелых ДТП.

## Задачи и методы
1.  **ETL:** Подключение к БД (`SQLAlchemy`), написание SQL-запросов с фильтрацией и объединением таблиц.
2.  **Препроцессинг и Feature Engineering:** Обработка пропусков, `OneHotEncoder`, `StandardScaler`. Устранена мультиколлинеарность. Созданы новые признаки (час ДТП, кластеры округов).
3.  **Моделирование:** Обучение и сравнение 4 моделей: `LogisticRegression`, `RandomForestClassifier`, `LGBMClassifier`, `CatBoostClassifier` с перебором гиперпараметров (`RandomizedSearchCV`).
4.  **Оценка:** Выбор метрики **ROC-AUC** (устойчива к дисбалансу).

## Стек
*   **Язык и БД:** Python, SQL (PostgreSQL), SQLAlchemy, Pandas.
*   **Препроцессинг:** Scikit-learn (`SimpleImputer`, `OneHotEncoder`, `StandardScaler`, `Pipeline`, `ColumnTransformer`).
*   **ML:** Scikit-learn (`LogisticRegression`, `RandomForestClassifier`), LightGBM, CatBoost.
*   **Оценка и интерпретация:** Scikit-learn (`roc_auc_score`), Phik, Matplotlib, Seaborn.

## Результаты и интерпретация

**Качество финальной модели (LogisticRegression):**
*   **ROC-AUC (test):** **0.6050** (на 10.5% лучше случайного угадывания).
*   **Recall (виновники):** 71% (модель находит ~5 из 7 виновников).
*   **Precision (виновники):** 59% (41% предупреждений — ложные).
*   **Accuracy:** 57%.

**Анализ важности признаков:**
*   **Час ДТП (доминирующий фактор):** Пик виновности приходится на вечерние часы — 17:00 (6.87% всех ДТП с виновниками), 18:00 (6.79%) и 19:00 (5.55%). Дневные часы (10–16) дают 31.4% всех ДТП.
*   **Тип автомобиля:** Седан (важность 0.5092).
*   **Регион:** Сельская/горная местность.

**Ключевые бизнес-выводы и рекомендации:**
1.  **Ограничения системы:** Модель можно использовать как **вспомогательный инструмент** для ранжирования рисков (Recall 71%), но **не для автоматического отказа** в выдаче авто (Precision 59%). Внедрение рекомендовано в формате MVP.
2.  **Что нужно для улучшения (до ROC-AUC 0.75–0.80):**
    *   *Данные о водителе:* стаж, возраст, история ДТП и штрафов.
    *   *Телематика:* средняя скорость, резкие ускорения/торможения.
    *   *Маршрутные данные:* плотность трафика, количество перекрестков.
3.  **Необходимость оборудования авто датчиками:**
    *   **GPS-трекер** и **акселерометр/гироскоп** (высокий приоритет) — для сбора данных о стиле вождения.
    *   **Алкотестер** (высокий приоритет) — исключение поездок в нетрезвом виде.
    *   **Камера на водителя** (средний приоритет) — контроль усталости и отвлечения.

**Итог:** Создание системы возможно. Рекомендуется внедрить MVP параллельно с установкой датчиков и сбором данных о водителях, используя модель для выдачи рекомендаций, а не для жестких ограничений.
